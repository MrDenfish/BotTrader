### Features Implemented

- **Observer plugin** (`daily_report_v2`): Accumulates risk events in memory, triggers report on UTC date rotation
- **FIFO P&L collector**: Deque-based buy queue per symbol, handles partial fills, computes wins/losses/by-symbol breakdown
- **Trade stats collector**: Aggregates buy/sell counts, volumes, fees from `v2_fills` table
- **Positions collector**: Reads open positions from `v2_positions` table
- **Signal stats collector**: Parses JSONL signal logs, counts by action and symbol
- **Risk event accumulator**: Tracks vetoes, circuit breaker trips, rejections in memory
- **Comparison collector**: Greedy signal matching between v1 (`scores.jsonl`) and v2 (`v2_score_log.jsonl`) within configurable time window
- **HTML renderer**: Jinja2 with inline CSS for email compatibility, custom `|money` and `|pct` filters, 9 report sections
- **Slack renderer**: Block Kit JSON with header, stats, P&L, comparison agreement rate with emoji indicators
- **Email delivery**: SES via boto3 or SMTP fallback, MIME multipart (text/plain + text/html)
- **Slack delivery**: aiohttp POST to webhook URL
- **CLI subcommand**: `python -m v2 report` with `--hours`, `--date`, `--send`, `--output` flags
- **Lazy DB pool**: asyncpg pool created on first report generation, not at observer init

### Problems Encountered and Solutions

1. **Plugin not auto-discovered by registry**
   - **Root cause**: `discover_plugins()` in `registry.py` skips `__init__` modules (line 170: `if leaf.startswith("_")`). The `@registry.plugin` decorator was in `__init__.py`.
   - **Fix**: Moved observer class to `observer.py`, `__init__.py` re-exports it.

2. **Test failure in full suite but not standalone**
   - **Root cause**: `test_registry.py` calls `registry.clear()` which removes all registrations. The `@plugin` decorator only fires once at import time, so subsequent `discover_plugins()` calls don't re-register already-imported modules.
   - **Fix**: Changed `test_plugin_registered` to explicitly call `registry.register()` instead of relying on `discover_plugins()`.

3. **SES mock patch path incorrect**
   - **Root cause**: `boto3` is imported lazily inside `_send_via_ses()`, not at module level, so `patch("...email.boto3")` fails.
   - **Fix**: Used `patch.dict("sys.modules", {"boto3": mock_boto3})` instead.

4. **RiskEvent has no `symbol` field**
   - **Root cause**: Test created `RiskEvent(event_type="veto", reason="low score", symbol="BTC-USD")` but the dataclass only has `event_type`, `reason`, `metadata`.
   - **Fix**: Removed `symbol=` kwarg from test.

### Lessons Learned

- The v2 registry's `discover_plugins()` skips `__init__.py` files — never put `@registry.plugin` decorators in `__init__.py`; always use a separate module (e.g., `observer.py`)
- When `registry.clear()` is called by other tests, `@plugin` decorators won't re-fire since modules are cached in `sys.modules` — test plugin registration by explicitly calling `registry.register()` rather than relying on `discover_plugins()`
- Lazy imports (like `import boto3` inside a function) require different mock patterns (`patch.dict("sys.modules")` instead of `patch("module.boto3")`)
- Jinja2's `PackageLoader` requires the package to be installed; `FileSystemLoader` with `Path(__file__).parent / "templates"` is more reliable for plugin directories

### Tips for Future Developers

- **Run a report manually**: `docker exec v2-paper python -m v2 report --config v2/paper_trading.yaml --hours 24` — prints text summary to stdout
- **Generate HTML locally**: `python -m v2 report -c v2/paper_trading.yaml --hours 24 --output /tmp/report.html` — requires DATABASE_URL env var
- **Auto-trigger**: Report fires on UTC date rotation at `report_hour_utc` (default 8) when there was activity that day
- **Add new collectors**: Create a module in `collectors/`, add a function that returns a dataclass, call it from `observer.py:generate_report()`
- **Add new delivery channel**: Create a module in `delivery/`, add config parsing in `observer.py.__init__()`, call from `_generate_and_send()`
- **Comparison requires both logs**: v1's `scores.jsonl` and v2's `v2_score_log.jsonl` must both exist in `/app/logs/` for the comparison section to populate
